# Moment Mark PRD（v0.2）

> 文档状态：可用于 AI 设计与开发的产品需求文档  
> 产品名称：Moment Mark / 刻间（暂定）  
> 视觉与页面结构唯一参考：`docs/design/proposal_J_final.html`  
> 补充页面参考：`docs/design/proposal_J.html`、`docs/design/proposal_J_app.html`  
> 优先级原则：现有 App 实现与上述最终设计稿优先于本文件中的抽象说明；如有冲突，应保留现有组件与最终设计稿的视觉风格，并更新本 PRD。

## 1. 一句话描述

Moment Mark 是一款供个人使用的“重要时刻 + 日常待办”App：用户在首页珍藏和关注重要日期，在日子簿安排当天任务，以像素冒险的世界观把未来的期待和过去的回忆留在同一个空间里。

## 2. 产品定位与目标

### 2.1 目标用户

- 以单个个人用户为对象。
- 当前不做账号、多设备同步、多人协作或共享。

### 2.2 要解决的问题

1. 用户想随时看到值得期待的未来日子，以及已经发生的重要时刻过去了多久。
2. 用户希望把重要回忆长期保存，但首版不需要复杂的相册或长篇日记系统。
3. 用户需要一个独立于首页大事件的日常待办空间，用于查看、完成和安排具体任务。

### 2.3 双体系定义

产品必须区分两类内容，不能用同一种新增入口或默认展示规则混淆：

| 体系 | 产品名称 | 语义 | 默认出现位置 |
| --- | --- | --- | --- |
| 重要时刻 | 时刻（Moment） | 未来是“倒数”，过去是“成就正数” | 首页“大事件” |
| 日常待办 | 任务（Task） | 面向未来的具体待办，可完成勾选 | 日子簿“副本地图” |

## 3. 设计原则与固定信息架构

### 3.1 视觉原则

- 使用 `proposal_J_final.html` 定义的“像素冒险”风格，不改造成普通 Dashboard、通用日历或极简待办工具。
- 当前主视觉稿的首页、日子簿、系统设置与封印之地均使用昼间“任务板”配色；洞窟夜间稿作为备选视觉暂存于 `proposal_J_final.html` 页面下方，不是当前默认页面样式。
- 时刻的未来状态使用倒数语义；过去状态使用成就/正数语义。
- 最终视觉、卡片样式、色彩、像素边框、文案世界观以设计稿为准；PRD 不重新规定具体颜色、字号或 CSS/Compose 实现方式。

### 3.2 底部导航与入口

底部导航固定为三个入口：

| 入口 | 页面 | 行为 |
| --- | --- | --- |
| `◉ 大事件` | 首页 | 查看全部重要时刻，进入时刻详情。 |
| `＋ 新时刻` | 铭刻时刻页 | 全局统一入口；只新增重要时刻，不创建待办。 |
| `▤ 日子簿` | 副本地图页 | 查看月历与选中日期的任务；从此页新增待办。 |

**不得**在首页或全局“新时刻”入口创建普通待办；**不得**在日子簿的“接受新任务”入口创建首页重要时刻。

## 4. 典型使用场景

### 场景 A：清晨安排今天

用户进入“日子簿”，默认定位今天。在“今日掉落”区域查看今天待办，例如“提交项目周报”“晚上买礼物”；完成一项后直接勾选，任务显示为 `CLEAR`。用户点击“接受新任务”可添加一条今日或未来日期的待办。

### 场景 B：闲暇时回看重要关系与回忆

用户进入首页“大事件”，看到置顶且占据整行的“和女朋友在一起”成就卡。进入详情页后，查看已经相伴的天数、开始日期和故事；后续可看到自动计算的里程碑。

### 场景 C：记录新发生的重要事情

发生“拿到 offer”等值得记住的事情时，用户点击底部 `＋ 新时刻`，选择“过去·正数”，填写标题和开始日期，选填故事、分组和重要度。保存后，它作为过去时刻显示在首页左列，并可以进入独立详情页。

### 场景 D：关注未来大事

用户通过 `＋ 新时刻` 创建“女朋友生日”“论文答辩”等未来时刻。保存后，该记录以倒数卡片显示在首页右列；用户点击卡片进入详情，查看剩余天数、日期和备注。

### 场景 E：未完成任务跨日

某条昨天的待办未完成。日期切换到今天后，它默认不出现在今天的“今日掉落”中，也不会自动迁移或删除。用户之后可进入对应日期或任务编辑页，主动将日期改为今天；后续版本再考虑自动迁移规则。

## 5. 页面与用户流程

### 5.1 首页：大事件（Home / Moments）

**目的：** 展示用户全部重要时刻；首页不是默认待办页。

**展示规则：**

1. 显示全部未被删除的时刻，页面可纵向滚动。
2. 被用户置顶的时刻排在最前方，且每条独占一整行的宽卡；多个置顶项支持用户手动调整顺序，并按该顺序展示。
3. 未置顶时刻以双列网格展示：左列只显示过去时刻（成就正数），右列只显示未来时刻（倒数）。
4. 每列按事件日期排序，而不是按创建时间排序：过去时刻按日期从近到远，未来时刻按日期从近到远（最近将到来的排在最前）。
5. 待办默认不在首页显示。仅当用户在待办详情/编辑中明确开启“显示在首页”时，才显示在首页右列；按所属/截止日期从近到远排序。到期当天可显示“就是今天”，日期过去后自动从首页隐藏，但仍保留在日子簿中；默认值必须为关闭。

**卡片最低信息：** 标题、事件日期、过去/剩余天数、状态类型。设计稿中的分组、重要度、进度等已有数据时应同步展示。

**进入与离开：**

- 点击时刻卡片 → 进入该时刻的详情页。
- 点击底部 `＋ 新时刻` → 进入“铭刻时刻”页。
- 点击 `▤ 日子簿` → 进入日子簿。

### 5.2 铭刻时刻：新增/编辑时刻（Moment Form）

**入口：** 底部全局 `＋ 新时刻`；编辑时由时刻详情页的“编辑”进入。同一个表单组件必须支持新增和编辑模式。

**操作流程：**

1. 用户先选择方向：`未来·倒数` 或 `过去·正数`。
2. 填写时刻名称和日期：未来·倒数只能选择今天或未来日期，过去·正数只能选择今天或过去日期。
3. 可选填写与设计稿一致的备注、分组和重要度；首页图标由所选分组路线决定。
4. 点击保存：新增时返回首页；编辑时返回原详情页；两种情况下均立即重新计算并展示天数。

**未来时刻的自动转换：** 未来倒数在目标日当天显示“就是今天”；从目标日的下一天起，自动转换为过去成就，保留同一条记录、标题、日期、备注、分组、重要度和置顶状态。转换后该条目从首页未来右列移动到过去左列，显示“已 X 天”，不创建重复记录。

**字段与校验：**

| 字段 | 适用模式 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 时刻方向 | 全部 | 是 | 未来=倒数；过去=正数。 |
| 时刻名称 | 全部 | 是 | 不允许为空。 |
| 目标日期 / 开始日期 | 全部 | 是 | 使用年/月/日三个独立选择格；未来只能选今天或未来，过去只能选今天或过去；按本地自然日保存。 |
| 任务背景 LORE / 成就故事 STORY | 全部 | 否 | 保存后显示在详情页。字段名称随模式变化。 |
| 分组线路 PARTY | 全部 | 否 | 如已有分组则选择；未选择时为“无阵营”。首页小卡图标自动使用该分组的图标。 |
| 重要度 RARITY | 全部 | 否 | 采用设计稿的星级表达。 |
| 置顶 | 全部 | 否 | 用户可在详情页将时刻置顶/取消置顶；置顶后遵循首页全宽排序规则。 |

**首版不提供：** 照片、视频、地点、心情、长篇富文本、系统通知和重复规则。

**本轮日期选择器契约（2026-09-01）：**

- 年、月、日必须是三个可独立操作的选择格，视觉按 `proposal_J_final.html` 的三格布局复刻；三格提交时合并为一个 `LocalDate` 事实字段。
- Moment 暂时一律为全天事件。日期面板左上角显示已勾选的 `[x] 全天` 标识；本轮不提供取消全天、时分选择或 `Instant` 字段。
- 三格的宽度、间距和父容器占比使用 Compose `weight`/相对布局表达，不写死屏幕宽度或卡片宽度；44dp 仅作为可访问触摸区域下限。

### 5.3 时刻详情：统一组件、两种展示模式（Moment Detail）

**目的：** 每一条时刻都必须有独立详情页；未来时刻和过去时刻共用同一页面组件，通过状态切换布局、主文案和可见区块。

**公共内容：**

- 标题、原始日期、分组、重要度。
- 编辑入口。
- 置顶/取消置顶入口。
- 删除入口（移入回收站，而非直接删除）。

**未来时刻模式：**

- 主视觉显示“X 天后开启”及目标日期。
- 显示任务背景 LORE（若已填写）。
- 可显示与该时刻关联的目标；关联能力为后续功能，首版不强制创建或完成“前置目标”。
- 目标日当天显示“就是今天”；次日起自动使用过去时刻模式展示。

**过去时刻模式：**

- 主视觉显示“已 X 天”及开始日期。
- 显示成就故事 STORY（若已填写）。
- 显示固定自动里程碑：100、365（一周年）、1000、1200、2000 天及后续固定节点；不能自定义、手工勾选或伪造完成状态。当前进行中的下一里程碑显示剩余天数、目标日期和金色时间条，已达成项显示达成日期，远期项显示“远征中”。

### 5.4 日子簿：副本地图（Daybook / Task Calendar）

**目的：** 是待办的默认页面与唯一新增入口，不承担首页“大事件”的默认展示职责。

**页面内容：**

- 月历：显示当前月份，可切换月份和选择某个日期。
- 选中日期的任务列表；当选中今天时标题显示为“今日掉落”。
- 每条任务显示完成状态、标题、截止日期/时间（若有）。
- “＋ 接受新任务（待办）”入口。

**展示与跨日规则：**

- 默认进入时选中今天。
- 创建某日任务后，仅显示在该日期的任务列表中。
- 未完成任务跨过所属日期后，不自动迁移到今天，不在今天任务列表出现，不自动删除。
- 用户可通过查看原日期或编辑任务，主动将任务日期修改到今天；“自动带入未完成任务”属于 P1。
- 任务完成后保留在所属日期的列表中：标题显示删除线，checkbox 填充勾选，右侧状态切换为 `CLEAR +5 EXP`；再次点击可取消完成并恢复未完成样式。

### 5.5 接受新任务：新增/编辑待办（Task Form）

**入口：** 仅从日子簿中的“＋ 接受新任务（待办）”进入；编辑时从任务条目/详情进入。同一个组件支持新增和编辑。

**流程：**

1. 用户选择快捷日期（今日、明日、本周六）或自选日期；新增默认选中今天。
2. 填写任务名称和截止日期；若使用精确时间，填写时间。
3. 可选填写任务描述 LORE、任务类型、难度、分组，并选择是否显示在首页；首页图标由所选分组路线决定。
4. 保存后返回对应日期的日子簿任务列表。

**字段与校验：**

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 任务名称 | 是 | 不允许为空。 |
| 所属/截止日期 | 是 | 默认今天；决定其在日子簿出现的日期。 |
| 截止时间 | 否 | 未填写时按全天任务处理。 |
| 任务描述 LORE | 否 | 可存攻略、备注或链接文本。 |
| 任务类型、难度、分组 | 否 | 采用最终设计稿的世界观表达；任务开启首页显示后，卡片自动使用分组图标。 |
| 显示在首页 | 否 | 默认关闭；开启后才允许显示在首页。 |

**任务完成：**

- 用户在日子簿列表点击复选框即可切换完成/未完成。
- 完成后更新为 `CLEAR +5 EXP` 状态并保留在原日期；标题显示删除线、checkbox 填充勾选；再次点击可取消完成并恢复 `TODO` 或具体截止时间。
- “经验值、闪光、音效、震动”等游戏化反馈可按设计稿实现，但不应影响任务完成状态的可靠保存。

### 5.6 回收站：封印之地（Trash / Graveyard）

**入口：** 设置页的“封印之地（回收站）”。

**删除流程：**

1. 用户在时刻或任务详情点击删除/放弃。
2. 弹出确认弹窗，明确说明该条目将被封存 30 天。
3. 用户确认后，该条目立即从原列表消失并移入回收站；显示可撤销的 Toast。
4. 用户可在 Toast 中立刻撤销，或在回收站中点击“复活”恢复。

**回收站规则：**

- 时刻和任务共用一个回收站，但必须标识内容类型。
- 回收站条目显示标题、删除时间、距离永久删除的剩余天数。
- 30 天内可复活；复活后恢复原始全部字段、完成状态和原显示位置规则。
- 用户可主动“永久净化”单条记录，或清空回收站；这两种操作都必须二次确认。
- 用户可在设置中决定是否开启“30 天后自动净化”，默认关闭。开启后仅在下一次打开 App 时清理已封存满 30 天的条目；不要求后台定时清理。关闭时，到期条目继续保留，直到用户手动净化。

### 5.7 本轮实施契约：成就详情与分组管理

`proposal_J_final.html` 的第三行第一张（⑦「成就详情」）和第四行第一张（⑩「分组管理」）作为本轮实施目标，详细的 UI/数据流/迁移方案见 [`docs/design/J_ROW3_ROW4_UI_LOGIC_PLAN.md`](docs/design/J_ROW3_ROW4_UI_LOGIC_PLAN.md)。本节锁定产品行为边界：

- 成就详情复用统一 Moment 详情路由。过去 Moment 显示 `AchievementFrame`、STORY 和日期派生的里程碑；未来 Moment 在目标日次日起自动进入同一成就表现。里程碑是只读派生投影，不落库、不允许手工伪造完成。
- 里程碑本轮只按固定日数节点和周年节点自动生成，不开放自定义；按目标日期排序。2 月 29 日开始的 Moment 在非闰年不生成周年项。周年提醒控件仍保持隐藏，直到通知链路另行交付。
- 分组管理从系统设置进入，不新增底部导航入口。分组拥有稳定 ID、名称、线路色 token、内置图标和排序；Moment/Task 通过各自的 `groupId` 归属，仍保持两套独立实体。首页小卡图标只取所属分组的图标，条目不单独保存图标。
- 新建/改名需名称 trim 后非空且不区分大小写唯一；解散分组必须二次确认，并在同一事务中把相关 Moment/Task 置为“无阵营”，不得删除、改动完成状态、置顶状态或封印状态。
- 分组卡片的活动计数默认排除 `deletedAt != null` 的项目，并区分 Moment/Task 类型；重启后名称、颜色、排序和归属保持。
- 这两屏虽然源自 P1 设计，本轮已明确授权实施；在实现过程中仍不得显示无行为的里程碑复选框或周年提醒开关。分组管理入口从系统设置进入，不新增底部导航。

### 5.8 本轮视觉与尺寸边界

- “这个时刻”方向选择严格采用 HTML 的双块布局：等宽、纵向图标+文字、未来蓝色选中态、过去金色选中态，未选中保持面板色和墨线。
- 分组、日历和任务行沿用 HTML 的像素冒险语言；卡片、日期格、三格日期选择器和列表行的宽度/间距优先使用父容器百分比、`weight` 或相对约束，不以固定屏幕尺寸实现。
- 日子簿日期格必须区分普通日、今天、选中日、其他月份和有任务日；有任务日显示 HTML 同风格内容标识。星期标题、字阶、间距以最终 HTML 为基准。

## 6. 业务规则与数据约束

### 6.1 时间计算

- 全日时刻按 `LocalDate`（本地自然日）计算；不得因时区或当天具体时刻导致天数跳变错误。
- 日期早于今天：过去状态，显示“已/已经过去 X 天”。
- 日期晚于今天：未来状态，显示“还有 X 天 / X 天后开启”。
- 日期等于今天：显示“就是今天”，不能只显示“0 天”。
- 用户以“未来·倒数”创建的时刻，在目标日次日起自动转为过去成就；原始日期与所有用户填写内容不变。
- 任务若填写精确截止时间，时间用于展示和未来提醒；首版的“所属日期”仍以本地自然日决定日子簿归属。

### 6.2 数据持久化

- 时刻、任务、分组、置顶状态、首页显示开关、完成状态和回收站信息必须本地持久化。
- 重启 App 后，数据和排序规则必须保持一致。
- 首版不要求账户登录、云同步或跨设备恢复。

### 6.3 重要时刻与待办的关系

- 时刻与任务是独立实体，分别创建、编辑、删除、归档。
- 允许任务主动开启“显示在首页”，但不会自动成为时刻，也不能改变时刻的过去/未来计算语义。
- 时刻详情中“关联前置目标”是后续可扩展能力，首版不要为了该展示而强制将任务绑定到时刻。

## 7. 功能优先级

### P0：首版必须完成

- 固定底部导航：大事件、全局新时刻、日子簿。
- 首页显示全部时刻：置顶全宽优先、过去左列、未来右列、按日期排序。
- 新增、编辑、查看、置顶与回收站删除时刻。
- 共用时刻详情页组件，支持未来倒数和过去正数两种状态。
- 日子簿月历与选中日期的任务列表。
- 仅从日子簿新增、编辑、删除任务；任务可勾选完成。
- 待办默认不显示在首页；可由用户手动开启在首页右列显示，并按日期排序。
- 未完成过期任务自动从“今天”隐藏，不自动迁移或删除。
- 30 天回收站、复活、永久删除、确认弹窗与删除后撤销；自动净化由用户设置且只在 App 打开时执行。
- 本地持久化，以及日期/状态在重启后的正确恢复。

### P1：重要，但在 P0 稳定后实现

- 时刻周年提醒、任务系统通知、提前提醒。
- 重复任务和“未完成任务自动迁移到今天”的可配置规则。
- 搜索、状态筛选和分组筛选。
- 更完整的任务详情、时刻与任务的前置目标关联。
- 桌面小组件。
- 将照片、地点、心情等扩展为时刻的附属回忆内容。

**本轮追加实施项（经用户确认，优先于常规 P1 排期）：**

- 固定自动里程碑与成就详情时间条；不允许自定义或手工勾选，2 月 29 日开始的 Moment 在非闰年不生成周年项。
- Room 分组、线路色、HTML 风格分组 chip、分组管理页及解散事务；不新增底部导航入口。
- Moment 年/月/日独立选择格与固定 `[x] 全天` 标识；不新增时分字段。
- 日子簿 HTML 风格日历与任务完成态：删除线、填充 checkbox、`CLEAR +5 EXP`。
- 分组的内置图标选择；首页小卡右上角保留固定尺寸图标槽，并自动显示所属分组的图标。无分组时显示统一默认图标。

### P2：锦上添花

- 模板/装备库与更多卡片皮肤。
- 数据导出、备份和恢复。
- 年度回顾。
- 多设备同步。
- 共享纪念日、共同任务和社交能力。
- AI 生成回忆文案或纪念建议。

## 8. 明确不做什么

以下内容不属于 P0，AI 或开发者不得在实现基础流程时自行扩展：

- 账号、登录、好友、多人协作、共享日历。
- 聊天、评论、点赞等社交功能。
- 照片、视频、长篇富文本日记。
- 系统通知、闹钟、重复任务、自动迁移未完成任务。
- 第三方日历、待办或云盘集成。
- 项目看板、子任务、番茄钟等复杂项目管理。
- 支付、会员和广告。

## 9. 验收标准

| 编号 | 功能 | 验收标准 |
| --- | --- | --- |
| AC-01 | 首页信息架构 | 打开 App 默认进入“大事件”；页面不默认展示日常待办，底部可进入日子簿。 |
| AC-02 | 新增未来时刻 | 从全局“新时刻”创建未来日期后，首页右列出现该卡片，并正确显示“还有 X 天”。 |
| AC-03 | 新增过去时刻 | 创建过去日期后，首页左列出现该卡片，并正确显示“已 X 天”。 |
| AC-04 | 今天状态 | 时刻日期等于今天时，界面明确显示“就是今天”，不只显示“0 天”。 |
| AC-04a | 未来转过去 | 将未来时刻的目标日推进到次日后，同一条目自动从未来右列移到过去左列，显示“已 X 天”；标题、备注、分组、重要度和置顶状态保持不变，且不生成重复记录。 |
| AC-05 | 置顶时刻 | 将某时刻置顶后，它位于首页最前方且独占一整行；取消置顶后按所在列的日期规则归位。 |
| AC-05a | 置顶排序 | 有两条及以上置顶时刻时，用户调整顺序后，首页全宽卡立即按新顺序展示；重启 App 后顺序保持。 |
| AC-06 | 首页排序 | 未置顶过去时刻只在左列、未来时刻只在右列；各列按日期从距离今天最近到最远排序。 |
| AC-07 | 时刻详情 | 点击任一时刻都进入独立详情页；未来和过去使用同一详情组件但显示各自的主文案和备注字段。 |
| AC-08 | 时刻编辑 | 编辑标题或日期后，返回详情/首页即可看到修改结果和重新计算的天数。 |
| AC-09 | 待办入口隔离 | 首页/全局新时刻无法创建普通待办；只有日子簿的“接受新任务”可创建待办。 |
| AC-10 | 新增待办 | 在日子簿创建一条默认日期为今天的待办后，它立即出现在“今日掉落”，初始状态为未完成。 |
| AC-11 | 任务完成 | 点击复选框后，标题显示删除线、checkbox 填充勾选，右侧显示 `CLEAR +5 EXP`；再次点击可恢复未完成并显示 `TODO` 或具体截止时间。 |
| AC-12 | 跨日隐藏 | 创建昨天的未完成任务后，切换到今天不会在“今日掉落”出现；它未被删除，编辑日期为今天后可重新出现。 |
| AC-13 | 首页显示开关 | 新建待办默认不显示在首页；用户显式开启后才显示，关闭后立即从首页移除但任务仍保留在日子簿。 |
| AC-13a | 首页待办排序 | 已开启首页显示的待办位于首页右列，按日期从近到远排序；到期当天显示“就是今天”，日期过去后自动隐藏但不删除。 |
| AC-14 | 软删除与撤销 | 删除时刻或任务会先出现确认；确认后从原页面消失、进入回收站，并提供即时撤销。 |
| AC-15 | 回收站复活 | 在 30 天内复活条目后，全部字段、完成状态和原排序/归属规则恢复。 |
| AC-16 | 永久删除 | 对单项永久净化、清空回收站或已开启自动净化后的 30 天到期删除，均不可恢复，且手动操作前有二次确认。 |
| AC-16a | 自动净化设置 | 自动净化默认关闭；用户开启后，重新打开 App 时仅清除已封存满 30 天的条目。关闭时不自动删除。 |
| AC-17 | 数据持久化 | 创建时刻、任务、置顶状态和已完成状态后，彻底关闭并重开 App，数据、状态及首页排序保持正确。 |
| AC-18 | 视觉一致性 | 页面使用最终设计稿的像素冒险风格与三入口信息架构；不得以新 Dashboard/通用待办布局替换既有设计。 |
| AC-19（本轮追加） | 成就里程碑 | 成就详情按固定 `Clock` 派生日数/周年里程碑，达到、下一项和远期项状态正确；不新增重复 Moment、不把派生状态写回数据库。 |
| AC-20（本轮追加） | 分组生命周期 | 新建/改名/解散分组经过名称校验与确认；解散后相关 Moment/Task 变为“无阵营”但字段、完成状态、置顶状态和封印状态保持，重启后结果一致。 |
| AC-21（本轮追加） | 分组计数与无障碍 | 分组卡片只统计活动项目并区分 Moment/Task；颜色来自主题 token；TalkBack、44dp 触摸目标和大字体布局可用。 |
| AC-22（本轮） | 三格全天日期 | Moment 使用独立年/月/日选择格，合并保存为一个 `LocalDate`；固定显示 `[x] 全天`，不提供时分。 |
| AC-23（本轮） | 固定里程碑 | 成就详情与首页成就卡按固定节点派生下一里程碑和金色时间条；不允许自定义或手工勾选；2 月 29 日在非闰年不生成周年项。 |
| AC-24（本轮） | HTML 方向块 | “这个时刻”未来/过去两块等宽并按 HTML 蓝/金选中态呈现，尺寸使用父容器比例。 |
| AC-25（本轮） | 日历视觉状态 | 日子簿月历按 HTML 风格区分今天、选中日、其他月份和有任务日，日期格与标题不得因固定小尺寸导致整体偏小。 |
| AC-26（本轮） | 分组线路 | Moment/Task 通过稳定 Group ID 选择线路色；管理页可新建、改名、排序和解散，解散后变为“无阵营”且不删除条目。 |
| AC-27（本轮） | 分组图标 | 每个分组持久化一个内置图标；Moment/Task 首页小卡在固定尺寸右上角图标槽自动显示所属分组图标。修改分组图标后，组内全部卡片同步更新；无分组时显示统一默认图标。 |

## 10. P0 完成定义

当用户能稳定完成以下端到端流程时，P0 才算完成：

1. 在全局“新时刻”分别创建一个过去时刻与一个未来时刻。
2. 在首页看到它们分别进入左列与右列，并正确显示正数/倒数。
3. 将其中一个时刻置顶，确认其变为首页顶部全宽卡；进入详情、编辑后数据正确更新。
4. 进入日子簿，创建今日待办、完成勾选，并确认它默认不占用首页。
5. 创建昨天的未完成待办，确认它不会自动跑到今天；主动改日期为今天后能再次看到。
6. 将一个时刻和一个任务移入回收站，分别验证撤销/复活和永久删除的边界。
7. 重启 App，确认上述数据、置顶、完成状态、排序及回收站剩余天数均正确保存。

## 11. 实施边界说明

- 本 PRD 定义产品行为、页面入口、数据归属和验收结果；不规定 Compose、Room、导航库或数据库表的具体实现。
- 不要把“设计稿中展示的所有未来能力”自动视为本轮范围；通知、重复任务、周年提醒、自定义里程碑、分组筛选等仍按本 PRD 的 P1/P2 执行。本轮追加的固定里程碑与分组管理除外。
- 每项实现完成后，应分别说明自动化测试、模拟器测试、真机测试以及尚未验证的部分；构建成功不等于产品流程已验证。
